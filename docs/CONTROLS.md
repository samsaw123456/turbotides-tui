**306 passed rows** cover every advertised physical binding in each relevant state, repeated input, disabled commands, recovery, records and contacts. Both six-circuit race/pace campaigns are included. Alternate keys are exercised separately through the actual PTY.

Letters mean unshifted keys. Arrows, Tab, Shift+Tab, Enter, Escape, Space, `?`, and Ctrl+C were sent separately. Focus-out/in messages and window-size changes were exercised.

Ordinary ANSI has no key-up identity. Throttle/brake are modes, steering expires after 180 ms without repeats, and Space/B/C are tap toggles. Repeat trains and explicit mode release were tested; physical key-release reporting and held mode-key behavior are not claimed. Standalone Shift, F11, controller, mouse and touch are not implemented game commands. [Additional Ctrl+Z and terminal-restoration probes](QUALITY_REVIEW.md) cover ignored job-control input in five game contexts and clean return to the shell.

## Escape protocol finding

The standalone [key probe](https://github.com/samsaw123456/turbotides-tui/blob/main/tools/key_protocol_probe.py) compiles [KeyProbe.java](https://github.com/samsaw123456/turbotides-tui/blob/main/tools/KeyProbe.java) against the frozen JAR and logs actual tui4j messages. All four live cases passed:

| Bytes / timing | Actual messages | Status |
| --- | --- | --- |
| One Escape, then 300 ms idle | `esc` | Passed |
| Ten Escape bytes, 40 ms apart from the outset | Five `alt+esc`; ignored by game | Passed: protocol observation |
| Initial Escape, 500 ms delay, ten 40 ms repeats | `esc`, then five `alt+esc`; initial press pauses, measured repeat sequence retains pause | Passed: measured hold sequence |
| Two isolated Escape taps, 300 ms apart | `esc`, `esc`; pause then resume | Passed |

An initial test incorrectly expected a rapid initial Escape byte burst to pause. The probe established Alt+Escape decoding, and the real game was retested with an isolated initial press and native repeat delay. **Tap Escape and wait for the pause screen.** Other repeat delays/counts can decode differently; holding toggles is unsupported. No claim is made that all held Escape streams remain paused. Evidence: `build/ansi-audit/key-protocol/`.
